# Code of Conduct

## The short version

Attack the design, not the person. This project is built on being told it is
wrong — one of its published claims was false for over a year and an outside
correction would have saved months. Blunt technical criticism is welcome and
expected. Contempt for people is not.

## Standards

Expected:

- criticism aimed at claims, code and specifications;
- saying what you have not verified, rather than asserting it anyway;
- accepting a correction without treating it as a defeat;
- assuming a confusing question comes from an unclear document, not a slow
  reader.

Not acceptable:

- personal attacks, harassment, or demeaning comments about anyone;
- sexualised language or imagery, or unwelcome attention of any kind;
- publishing anyone's private information without explicit permission;
- sustained disruption of discussions.

This applies in issues, pull requests, commit messages, and anywhere someone
is representing the project.

## Reporting

Report through **GitHub private vulnerability reporting** on this repository,
or by contacting the maintainer directly through GitHub. Reports are handled
privately.

> Maintainer note: a dedicated contact address should replace this paragraph
> before the project invites wider participation. Routing conduct reports
> through GitHub alone is workable for a solo project and will not scale.

## Enforcement

The maintainer will review reports and may warn, remove contributions, or
block accounts. For a project this size there is no committee and no appeals
process; that is a limitation worth stating plainly rather than pretending
otherwise.
